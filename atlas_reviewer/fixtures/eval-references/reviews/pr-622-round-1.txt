### Major

**`atlas_reviewer/tests/test_domain.py:88`: `# noqa: DTZ001` is an unused suppression under the pinned ruff, and RUF100 fails on it.**
Lenses: `auditing-enforcement-and-meta-artifacts` (unused/stale suppression) and `reviewing-pr-and-process-hygiene` (claims vs. evidence). Evidence: ruff `RUF100`.

- `requirements.txt` pins `ruff==0.17.4` (hash-verified, installed into a fresh venv by `ci.yml`). Under that pin, `DTZ001` is **not** in the default rule set: `ruff check --show-settings` lists `DTZ002`/`DTZ003`/`DTZ004` but not `DTZ001`.
- `pyproject.toml` adds `RUF100` through `extend-select`, so a `# noqa` naming a rule that isn't enabled fails plain `ruff check .`.

Reproduced with a venv built from `requirements.txt`, using the project's own invocation and no override flags:

```
$ ruff --version            # 0.17.4
$ ruff check .              # PR head 3fd6074
RUF100 [*] Unused `noqa` directive (non-enabled: `DTZ001`)
  --> atlas_reviewer/tests/test_domain.py:88:36
Found 1 error.

$ git show origin/main:atlas_reviewer/tests/test_domain.py | ruff check --stdin-filename atlas_reviewer/tests/test_domain.py
All checks passed!          # base, without the directive
```

The `DTZ001` hit the description reports only shows up under an **unpinned** ruff. The authoring sandbox's global `ruff 0.16.9` does enable DTZ001 and does pass with this change. So these three claims are true for 0.16.9 but not for the version this repo gates on:

- the description's "`ruff check .` currently fails on `main`"
- the description's "now passes"
- the commit message's "ruff's default-enabled DTZ001"

The concurrency-cancelled CI runs aren't masking a failure on `main`, because under the pin there isn't one.

**Suggested resolution:** drop the directive. If nothing else is in the PR, close it, since `main` is already clean under the pin. If a future ruff bump re-enables DTZ001 by default, add the `noqa` in that bump PR, where RUF100 will accept it.
